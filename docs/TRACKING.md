# Suivi de trajet — Phase 3

Mise à jour phase 4 : [fiabilité et résultats](TRACKING-PHASE4.md), [production et rollback](PRODUCTION.md). Le GPS est maintenant global ; les JWT STOMP sont contrôlés pendant toute la connexion et les emails SOS passent par une file durable.


**Flux.** React/MapLibre → STOMP natif `/ws` → Spring → Redis (position 120 s), PostgreSQL (jalons/événements 30 jours). OSRM a 2 s de délai maximum ; son échec produit une ligne droite ×1,3. Spring Boot 3.1 utilise `RestTemplate` (le `RestClient` du prompt nécessite Spring 6.1). Marche/vélo : géométrie voiture, durée estimée. Aucune clé payante.

**Accès.** JWT uniquement dans CONNECT. Topics privés `/topic/tracking.{id}`, `/topic/session.{id}.status` : participants/admin ; `/user/queue/notifications`, `/user/queue/errors` ; `/topic/admin.alerts` : admin. Les positions entrantes sont réservées au prestataire. Aucun historique GPS continu. Les snapshots et liens publics ne révèlent plus de position après arrivée/annulation/fin ; les liens sont immédiatement révoqués (priorité à cette règle de confidentialité plutôt qu’au maintien une heure après l’arrivée). Les coordonnées publiques sont arrondies ; les prestataires disponibles sont floutés sur une grille ~200 m.

**Hypothèses.** Le prestataire rejoint le point obligatoire choisi par le client. `ACCEPTED` signifie désormais réservation acceptée ; les anciennes lignes sont migrées une seule fois en `IN_PROGRESS`. Le client complète les anciennes réservations sans rendez-vous depuis la fiche séance. L’arrivée exige deux points à moins de 50 m. Le code démarre la séance ; seul le prestataire la termine. Annulation sans délai pendant le trajet ; règle 24 h avant départ, sauf SOS. Arrêter le partage annule la séance. Aucun partage du GPS live du client. Le SOS alerte l’équipe et envoie des emails aux contacts ; les numéros de téléphone sont conservés comme contacts, aucun SMS n’est envoyé. Il n’appelle jamais les secours. Après arrivée, l’email SOS renvoie à Mazlove sans position live.

**Configuration.** `OSRM_BASE_URL`, `OSRM_TIMEOUT_MS`, `PUBLIC_BASE_URL`, `VITE_MAP_STYLE_URL`, `VITE_MAP_STYLE_DARK_URL` (fond de carte du mode nuit, OpenFreeMap « dark » par défaut), `VITE_DEMO` ; `TRACKING_ARRIVAL_RADIUS_M` (50), `TRACKING_ARRIVAL_CONSECUTIVE_PINGS` (2), `TRACKING_DEVIATION_THRESHOLD_M` (400), `TRACKING_DEVIATION_DURATION_S` (60), `TRACKING_SIGNAL_LOST_AFTER_S` (45), `TRACKING_MAX_ACCURACY_M` (100), `TRACKING_MAX_SPEED_MPS` (70), `TRACKING_ETA_REFRESH_S` (30), `TRACKING_RETENTION_EVENTS_DAYS` (30), `TRACKING_SHARE_TTL_AFTER_END_H` (1). Le serveur marqueur garde sa propre heure. La route et les indicateurs Redis expirent également. La disponibilité publique est facultative, retirée après 90 s sans mise à jour.

**Démo.** `make demo`, ouvrir `/demo`, « Lancer ». La barre accepte le consentement des comptes fictifs ; pour tester le modal, utiliser la console. Six scénarios, même pipeline que le vrai GPS. Vitesse accélérée plafonnée à 60 m/s pour conserver l’anti-téléportation. `dev` seulement ; `dev+prod` ou OTP fixe en `prod` font échouer le démarrage. `make simulate SESSION=… SCENARIO=DEVIATION`. Les fixtures ont été enregistrées via OSRM ; tests sans appels au routage public. Le CLI rejoue du GeoJSON ou des points GPX en les interpolant sous le seuil anti-téléportation.

**Validation.** `cd backend && mvn test` ; `cd frontend && npm ci && npm test && npm run build`. PostgreSQL/Redis locaux requis pour `MAZLOVE_STOMP_IT=true mvn -Dtest=StompSecurityIT test` ; ce test ne lance pas Docker. Après `make demo` : `cd frontend && npx playwright install chromium`, puis `make e2e`. Les tests navigateur/integration sont livrés mais doivent être exécutés avec les services. Le test E2E vérifie le snapshot nettoyé ; le test STOMP vérifie directement Redis.

**Déploiement.** Exécuter le schéma avant Hibernate si `DB_INIT_MODE=never`. En production : `SPRING_PROFILES_ACTIVE=prod`, `VITE_DEMO=false`, secrets et HTTPS. La PWA doit rester visible avec écran allumé (Wake Lock) ; V2 native/Capacitor pour l’arrière-plan. Le broker simple nécessite un relais RabbitMQ ou Redis pub/sub pour plusieurs instances. OpenFreeMap et OSRM publics n’ont pas de SLA : prévoir tuiles avec SLA et OSRM hébergé. `make osrm-prepare` télécharge plusieurs centaines de Mo (prévoir plusieurs Go de disque/mémoire, quelques minutes à dizaines de minutes), puis `docker compose --profile routing up` et `OSRM_BASE_URL=http://osrm:5000`. Aucun Docker lancé pendant cette livraison.
